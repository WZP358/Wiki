# 功能对照清单

## 通用要求

- 基础登录/注册：已完成。
- 注册验证码：已完成；测试模式会返回验证码，便于现场演示。
- 权限控制：已完成；区分普通用户、系统管理员、知识库成员角色。
- API 文档：已接入 Swagger/Knife4j，核心接口文档已维护。
- 异常处理和日志：已完成；统一业务异常、操作日志和后台审计入口。

## Wiki 核心功能

- 文档管理：已完成；支持树形目录、Markdown 编辑、预览和最终排版查看。
- 图片插入：已完成；支持文档图片上传。
- 版本历史：已完成；支持保存历史、版本对比、回滚。
- 全文检索：已完成；使用数据库 LIKE 查询标题和正文。
- 文档权限：已完成；公开、团队可见、私有均在“知识库可见”前提下生效。
- 文档标题唯一：已完成；同一知识库重名会自动追加 `（1）`、`（2）`。

## Redis 缓存应用

- 最近更新文档：已完成；展示前 5 个。
- 热门文档：已完成；展示前 5 个。
- 文档 HTML 缓存：已完成；发布/更新后刷新缓存。
- 用户编辑锁：已完成；使用 `editing:docId` 防止多人覆盖，并支持催一下。
- 缓存一致性：已完成；文档创建、更新、删除、回滚会清理相关缓存。

## 用户与团队逻辑

- 新用户注册后待分配：已完成；默认没有团队、职位和业务协作权限。
- 待分配用户后台提醒：已完成；系统管理员可单独处理待分配账号。
- 团队树：已完成；数据库数据已改成项目团队/子团队/任务组。
- 团队知识库归属：已完成；知识库拥有独立 `teamId`，不会随创建者调团队漂移。
- 可见不等于可编辑：已完成；公开/团队可见只代表可读，编辑必须来自知识库成员角色。

## 知识库协作逻辑

- 知识库创建者自动成为管理员：已完成。
- 每个知识库至少一名管理员：已完成。
- 知识库管理员邀请普通用户：已完成。
- 管理员账号不作为普通协作者：已完成；邀请成员时只允许普通用户。
- 子知识库：已完成；父知识库管理员可创建，点击子知识库直接跳转。
- 子知识库权限策略：已完成；子知识库是独立空间，不自动继承父知识库成员权限。

## 删除与恢复

- 普通用户无回收站入口：已完成。
- 知识库管理员软删除文档：已完成。
- 系统管理员审计和恢复删除内容：已完成。
- 文档永久删除：已禁止；当前业务只允许软删除和恢复。

## 前端体验

- 用户端浅色主题：已完成。
- 统一提示框/警告框/加载状态：已完成核心页面。
- 用户端复用 Element/RuoYi 风格组件：已完成核心页面。
- 后台管理复用 RuoYi 风格：已完成 Wiki 管理核心页面。
- 菜单和核心文案统一为“团队”：已完成核心业务页面。

## 仍需注意

- 若依原生 `system/dept` 模块内部代码和注释仍保留 `dept/department` 命名，这是框架兼容字段，不影响业务展示。
- 部分历史说明文档仍可能提到旧“部门”模型，评审以本清单和 BDD 文档为准。

# 知识库增删改查问题诊断指南

## 问题描述
无法对知识库进行增删改查操作

## 可能的原因和解决方案

### 1. 认证问题

**症状**: 所有API请求返回401未授权错误

**检查步骤**:
1. 打开浏览器开发者工具 (F12)
2. 查看 Application/Storage -> Local Storage
3. 确认是否存在 `wiki-token` 键

**解决方案**:
- 如果token不存在，需要重新登录
- 如果token存在但无效，清除token并重新登录

### 2. 后端服务未启动

**症状**: 前端请求失败，显示网络错误

**检查步骤**:
```bash
# 检查后端是否运行
curl http://localhost:8080/api/auth/me

# 或在Windows PowerShell中
Invoke-WebRequest -Uri http://localhost:8080/api/auth/me
```

**解决方案**:
```bash
# 启动后端服务
cd backend
mvn spring-boot:run

# 或使用启动脚本
./start-backend.cmd
```

### 3. 数据库连接问题

**症状**: 后端启动失败或API返回500错误

**检查步骤**:
1. 查看后端日志中的数据库连接错误
2. 确认MySQL服务是否运行
3. 检查 `backend/src/main/resources/application.yml` 中的数据库配置

**解决方案**:
```bash
# 启动MySQL服务 (Windows)
net start MySQL80

# 检查数据库是否存在
mysql -u root -p
USE wiki;
SHOW TABLES;
```

### 4. 数据库表未创建

**症状**: API返回表不存在的错误

**检查步骤**:
```sql
-- 连接到MySQL
mysql -u root -p

-- 检查knowledge_bases表是否存在
USE wiki;
SHOW TABLES LIKE 'knowledge_bases';
DESC knowledge_bases;
```

**解决方案**:
```bash
# 执行数据库初始化脚本
cd backend/sql
mysql -u root -p wiki < schema-mysql8-with-fk.sql
```

### 5. CORS跨域问题

**症状**: 浏览器控制台显示CORS错误

**检查步骤**:
- 打开浏览器开发者工具 -> Console
- 查看是否有 "CORS policy" 相关错误

**解决方案**:
已配置CORS，如果仍有问题，检查 `backend/src/main/java/com/wiki/app/config/WebConfig.java`

### 6. 前端代理配置问题

**症状**: API请求404或路径错误

**检查步骤**:
查看 `frontend/vite.config.js` 中的proxy配置

**解决方案**:
确保前端开发服务器正确代理到后端:
```javascript
// vite.config.js
export default {
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true
      }
    }
  }
}
```

### 7. 静态部署/跨域直连导致的 API 路径问题（最常见）

**症状**：开发环境正常；一旦用 `frontend/dist` 静态部署或直接打开页面，知识库 CRUD 全部失败（常见 404/Network Error）。

**原因**：前端默认使用相对路径 `'/api'`，需要“同域反向代理”或“显式配置后端 API 地址”。

**解决方案（二选一）**：

- **方案 A（推荐）**：为前端配置 `VITE_API_BASE_URL`，指向后端 API 根路径（以 `/api` 结尾）
  - 示例：`VITE_API_BASE_URL=http://localhost:8080/api`
  - 示例文件：`frontend/env.example`
- **方案 B**：在 Nginx/网关中把 `/api` 反向代理到后端，再托管前端静态文件

## 使用测试工具诊断

我已经创建了一个测试工具: `test-kb-api.html`

**使用方法**:
1. 确保后端服务正在运行
2. 在浏览器中打开前端应用并登录
3. 在新标签页打开 `http://localhost:5173/test-kb-api.html` (或前端服务的实际地址)
4. 点击各个测试按钮，查看详细的API响应

## 详细的API测试步骤

### 测试1: 检查认证状态
```bash
# 使用curl测试 (需要替换YOUR_TOKEN)
curl -H "Authorization: Bearer YOUR_TOKEN" http://localhost:8080/api/auth/me
```

### 测试2: 获取知识库列表
```bash
curl -H "Authorization: Bearer YOUR_TOKEN" http://localhost:8080/api/kbs/mine
```

### 测试3: 创建知识库
```bash
curl -X POST http://localhost:8080/api/kbs \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "测试知识库",
    "type": "PRIVATE",
    "description": "这是一个测试"
  }'
```

### 测试4: 更新知识库
```bash
curl -X PUT http://localhost:8080/api/kbs/123456 \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "更新后的名称",
    "type": "PRIVATE",
    "description": "已更新"
  }'
```

### 测试5: 删除知识库
```bash
curl -X DELETE http://localhost:8080/api/kbs/123456 \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## 常见错误代码

- **401 Unauthorized**: Token无效或已过期，需要重新登录
- **403 Forbidden**: 没有权限执行该操作
- **404 Not Found**: 知识库不存在或已被删除
- **500 Internal Server Error**: 服务器内部错误，查看后端日志

## 查看后端日志

后端日志会显示详细的错误信息:

```bash
# 如果使用mvn运行，日志会直接输出到控制台
cd backend
mvn spring-boot:run

# 查看日志文件 (如果配置了日志文件)
tail -f backend/logs/application.log
```

## 前端调试技巧

1. **打开浏览器开发者工具** (F12)
2. **Network标签**: 查看所有API请求和响应
3. **Console标签**: 查看JavaScript错误
4. **Application标签**: 查看LocalStorage中的token

# 高可用与监控部署说明

## 健康检查

- 后端已接入 Spring Boot Actuator。
- 可公开探活端点：
  - `GET /actuator/health`
  - `GET /actuator/health/liveness`
  - `GET /actuator/health/readiness`
- 可用于 Nginx、Kubernetes、Docker Compose、云负载均衡的健康检查。

## 监控

- 已暴露基础监控端点：
  - `GET /actuator/metrics`
  - `GET /actuator/info`
- 生产环境建议接入 Prometheus + Grafana。
- 建议重点监控：
  - JVM 内存、GC、线程数
  - HTTP 请求耗时与错误率
  - MySQL 连接池状态
  - Redis 连接状态
  - 文档编辑、搜索、登录接口的 P95/P99 延迟

## 高可用部署

推荐生产拓扑：

```text
Client
  -> Nginx / Cloud Load Balancer
  -> wiki-backend instance 1
  -> wiki-backend instance 2
  -> MySQL primary / replica
  -> Redis primary / replica or Redis Sentinel
```

- 后端是无状态 JWT 架构，可以横向扩展多实例。
- WebSocket 协作建议在同一文档会话开启粘性会话，或后续改造成 Redis Pub/Sub 跨节点广播。
- MySQL 建议使用主从复制；读多写少场景可扩展读写分离。
- Redis 建议使用 Sentinel 或云 Redis 高可用版。

## 备份策略

需要定期备份：

- MySQL 数据库：用户、知识库、文档、版本、评论、日志等核心数据。
- `wiki.local-storage-dir`：已发布 HTML 等本地文档产物。
- `wiki.avatar-storage-dir`：用户头像文件。

建议策略：

- 每日全量备份 MySQL。
- 每小时增量 binlog 归档。
- 本地文件目录每日归档到对象存储或备份盘。
- 每月至少做一次恢复演练，确认备份可用。

## 容错与恢复

- 进程级自动恢复：systemd、Docker restart policy 或 Kubernetes Deployment。
- 服务级故障切换：负载均衡健康检查自动摘除异常实例。
- 数据级恢复：MySQL 通过备份 + binlog 恢复到指定时间点。
- Redis 缓存可重建，业务数据以 MySQL 为准。

## API 版本策略

- 当前保留原有 `/api/...` 路径。
- 新增 `/api/v1/docs/...` 文档接口版本入口，兼容已有文档核心操作。
- 重大接口变更时新增 `/api/v2/...`，旧版本保留一个迁移周期。
